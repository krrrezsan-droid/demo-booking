# Ревью исходного BookingController

Ревью относится к версии до локальных исправлений. `index` и `today` оставлены без функциональных изменений.

| Место | Серьёзность | Проблема и исправление |
| --- | --- | --- |
| `store`, SQL | critical | Прямая интерполяция `room_id`, `starts_at`, `ends_at` позволяет SQL-инъекцию. Валидировать вход и использовать параметризованные запросы Query Builder. Исправлено. |
| `store`, автор | critical | `create($request->all())` принимает разрешённый моделью `user_id`: можно создать бронь от чужого имени. Явно брать автора из аутентифицированного пользователя, сохранять только выбранные поля. Исправлено; присланный `user_id` игнорируется. |
| `destroy` | critical | Любой авторизованный пользователь удаляет любую бронь по id. Проверять автора до удаления; чужая бронь возвращает 403, отсутствующая — 404. Исправлено. |
| `store`, границы | major | `<=` и `>=` запрещают соседние интервалы. Пересечение полуоткрытых интервалов: `existing.start < new.end AND existing.end > new.start`. Исправлено. |
| `store`, вход | major | Нет проверки обязательных полей, существования комнаты, длины названия и дат. Возможны исключения и 500 вместо 422, относительные даты и даты без смещения. Добавлен FormRequest с ошибками по полям. |
| `store`, время | major | Проверяется только час начала в смещении клиента. Нет проверки окончания, длительности, шага, секунд, перехода суток и часового пояса офиса. Теперь проверяется весь интервал в часовом поясе комнаты, длительность 15–240 минут, обе границы кратны 15 минутам. |
| `store`, хранение | major | `timestamp without time zone` не сохраняет смещение; Eloquent форматирует дату для SQL без него. Без нормализации одинаковые моменты могут храниться как разные. Исправлено: запись и сравнение в UTC; локальное время используется только для рабочих часов. Существующие данные с неизвестным исходным смещением нельзя надёжно исправить автоматически. |
| `store`, гонка | major | Между проверкой конфликта и вставкой другой запрос может создать бронь. Проверка и вставка перенесены в транзакцию с блокировкой строки комнаты. Подробности и границы гарантии — в README. |
| `today`, дата | major | `today()` использует часовой пояс приложения, а `whereDate` — календарную дату хранимого timestamp. Для Москвы и Новосибирска день начинается в другой момент. Нужно вычислять начало и конец местного дня комнаты и переводить границы в UTC для диапазонного запроса. |
| `today`, авторы | minor | `$b->user` в цикле создаёт N+1 запросов. Загружать `with('user')`. |
| `today`, выдача | minor | Нет сортировки по началу; строка времени не переводится в зону офиса. Добавить `orderBy('starts_at')` и явную сериализацию локального времени со смещением. |
| `index`, порядок | minor | При равных `starts_at` порядок неопределён, возможна нестабильная пагинация. Добавить вторичный порядок по `id`; при больших объёмах рассмотреть составной индекс `(user_id, starts_at, id)`. |
| логирование | minor | `Log::withContext` добавляет контекст стандартному каналу, затем запись идёт в отдельный канал `bookings`: id не гарантирован в этой записи. Исправлено передачей контекста непосредственно в `info`. Ошибка файлового лога после коммита всё ещё может вернуть 500 при сохранённой записи; для строгой гарантии доставки нужен transactional outbox. |
| API без Accept | minor | В исходной конфигурации неаутентифицированный запрос без `Accept: application/json` пытается перейти на отсутствующий login route. Для API стоит настроить JSON-ответы по префиксу `api/*`; пока заголовок явно требуется в README. |

## Подозрительно, но не является дефектом

- `orderByRaw('starts_at DESC')` в `index` не содержит пользовательских данных и не создаёт SQL-инъекцию. `orderByDesc` был бы проще, но не безопаснее в данном случае.
- `index` фильтрует по аутентифицированному пользователю; доступ к чужим броням через эту выборку не обнаружен.
- `Fillable` работает: произвольный `id` не сохраняется. Однако разрешённый `user_id` не заменяет проверку прав.
- Маршруты уже защищены Sanctum. Это обеспечивает аутентификацию, но не авторизацию отмены.
- `findOrFail` корректно возвращает 404, когда запись отсутствует. Для нечислового id добавлено ограничение маршрута, чтобы PostgreSQL не получал неподходящий тип.
- Прошедшие даты, выходные, далёкое будущее и несколько непересекающихся броней одного пользователя разрешены: ТЗ не запрещает их.
- Окончание ровно в 20:00 допустимо; начало в 20:00 при положительной длительности — нет.
- `timestamp without time zone` допустим при единой договорённости о UTC для всех писателей. Внешние записи обязаны соблюдать её.


## Дополнения после перепроверки

- **minor — JSON-тип комнаты:** обычное правило Laravel `integer` принимает boolean `true`, строку `"1"` и число `1.0`. Исправлено на `integer:strict`, закреплено HTTP-тестами при существующей комнате №1.
- **minor — момент логирования:** при внешней транзакции завершение вложенного `DB::transaction` ещё не означает сохранение данных. Лог перенесён в `DB::afterCommit`; тесты подтверждают отсутствие записи до коммита и после отката.
- **minor — локальное окружение:** исходный Compose публикует порт на всех интерфейсах. Для этого демонстрационного запуска установлен `127.0.0.1:8000:8000`.
- Возврат только что созданной Eloquent-модели из исходного `store` сам по себе не является ошибкой статуса: Laravel автоматически выставляет 201 для `wasRecentlyCreated`. Наш явный JsonResponse делает контракт видимым, но не исправляет отсутствовавший дефект.
- Результат проверки конкурентности теперь подтверждён отдельным процессом, наблюдением блокировки и проверкой чувствительности теста к удалению блокировки; подробности — README.
